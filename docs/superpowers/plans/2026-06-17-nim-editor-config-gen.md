# Nim Editor Config Generation (`zapp/nim.cfg`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make nimsuggest / nimlangserver resolve `import zapp` in an app's `zapp/app.nim` by having the CLI generate a gitignored `zapp/nim.cfg` at `zapp init` and refresh it on every Nim build.

**Architecture:** A pure renderer (`renderNimCfg`) emits the cfg text (two absolute `--path` lines + `--mm:orc --threads:on` + a "do not edit" header). The Nim build (`buildNativeNim`) writes it after computing the framework + `.zapp` paths it already has; `zapp init` writes it next to the scaffolded `app.nim` and gitignores it. The build is unchanged as the source of truth — the cfg is editor-only.

**Tech Stack:** TypeScript (Bun), `bun:test`, the Nim compiler's `nim.cfg` config format.

**Spec:** `docs/superpowers/specs/2026-06-17-nim-editor-config-gen-design.md`

- [ ] **Step 3: Implement `renderNimCfg`.** In `cli/src/build-config.ts`, after `renderHeadlessNim` (the function ending ~line 292), add:

```ts
export interface NimCfgOpts {
  frameworkNimDir: string; // absolute path to the framework's native/nim
  zappDir: string;         // absolute path to the project's .zapp dir
}

/**
 * Render `zapp/nim.cfg` — the editor (nimsuggest / nimlangserver) config that
 * lets `import zapp` resolve in an app's zapp/app.nim. Mirrors the two `--path`
 * values the Nim build passes (native/nim + the generated .zapp/ modules) plus
 * the build's memory/thread flags so the LSP's semantic checks match the real
 * compile. CLI-owned + gitignored: regenerated each build (see buildNativeNim)
 * and at `zapp init`. Both paths are ABSOLUTE so nimsuggest never has to guess
 * which directory a relative cfg path resolves against. Pure (no disk I/O).
 */
export function renderNimCfg(o: NimCfgOpts): string {
  // Forward slashes so the value is benign inside the cfg on Windows too.
  const fw = o.frameworkNimDir.replace(/\\/g, "/");
  const zapp = o.zappDir.replace(/\\/g, "/");
  return `# GENERATED by \`zapp build\`/\`zapp init\` — do not edit.
# Lets nimsuggest/nimlangserver resolve \`import zapp\` (and the framework's
# transitive imports + the generated .zapp/ modules). Regenerated each build.
# Custom flags? Add zapp/app.nim.cfg or zapp/config.nims (the CLI won't touch those).
--path:"${fw}"
--path:"${zapp}"
--mm:orc
--threads:on
`;
}
```

### Task 2: Write `zapp/nim.cfg` from the Nim build

**Files:**
- Modify: `cli/src/native.ts` (`buildNativeNim`, around line 1232 where `nimFrameworkDir` is computed)

- [ ] **Step 1: Write the cfg in `buildNativeNim`.** In `cli/src/native.ts`, the block that builds the `nim c` args computes `const nimFrameworkDir = path.join(nativeDir, "nim");` (~line 1232). Immediately AFTER that line, add the cfg write (it reuses `zappDir` computed earlier in the function and `root` for the `zapp/` dir; `renderNimCfg` comes from `./build-config`):

```ts
  // Editor config: write zapp/nim.cfg so nimsuggest/nimlangserver resolve
  // `import zapp` with the SAME paths this build uses. Gitignored + regenerated
  // each build (the build itself passes --path explicitly; this file is purely
  // for the editor). Best-effort: never fail the build over the editor cfg.
  try {
    const { renderNimCfg } = await import("./build-config");
    const appZappDir = path.join(root, "zapp");
    await fs.mkdir(appZappDir, { recursive: true });
    await fs.writeFile(
      path.join(appZappDir, "nim.cfg"),
      renderNimCfg({ frameworkNimDir: nimFrameworkDir, zappDir }),
      "utf-8",
    );
  } catch { /* editor cfg is non-fatal */ }
```

(`fs` is the `node:fs/promises` import already bound at the top of `buildNativeNim`; `zappDir` is `path.join(root, ".zapp")` computed earlier in the function.)

## Self-review notes

- **Spec coverage:** renderer (Task 1) ✓; build-writes-cfg (Task 2) ✓; init scaffolds + gitignores (Task 3) ✓; kitchen-sink migration (Task 4) ✓; docs + LSP gate (Task 5) ✓; "out of scope — no change to build `--path`" honored (Task 2 only ADDS a file write, leaves the `args` array untouched) ✓; nimble future-possibility is spec-only (no task) ✓.
- **Type consistency:** `renderNimCfg({ frameworkNimDir, zappDir })` — same object shape in the renderer (Task 1), the build call (Task 2), and the init call (Task 3). Both fields are absolute paths in all three.
- **`zappDir` reuse (Task 2):** `buildNativeNim` already binds `const zappDir = path.join(root, ".zapp")` near its top and `const nimFrameworkDir = path.join(nativeDir, "nim")` in the args block — the cfg write uses both, so no new path computation is introduced.
- **Non-fatal writes:** the build wraps the cfg write in try/catch so an editor-only artifact can never break a build (matches the "build is source of truth" principle).
- **Idempotence:** the cfg is fully regenerated (overwrite) each time, so repeated builds/inits converge; no append/dedup logic needed.
